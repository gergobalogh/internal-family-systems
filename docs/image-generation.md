# Generating images with Nano Banana in AI Studio

How the world plates and creatures in `src/assets/` were made, and how to make
more. We drive the **AI Studio web page** (aistudio.google.com) in a real
Chrome window that you are logged into. We don't use the API. Scripts in
`scripts/studio/` type the prompt, wait for the image and save it, and you
can watch every step in that window.

Model: **Nano Banana 2.1** (`gemini-nano-banana-2.1`). Each image is billed to
the Google Cloud project behind your AI Studio account. This session made
five: day, dusk and three creatures.

## How it works

1. Chrome is started with a **remote debugging port** (127.0.0.1:9222) and its
   own profile. You log in to Google there once, by hand.
2. Playwright (`playwright-core`, a dev dependency) **attaches** to that window
   with `chromium.connectOverCDP()`. It doesn't launch a browser of its own.
   It finds the tab whose URL contains `aistudio.google.com/prompts`.
3. `generate.mjs` fills the "Enter a prompt" box, presses Ctrl+Enter and polls
   every 3 s. It waits until a new image appears in the chat or an error turn
   does.
4. The image is a `blob:` URL inside the page, so the script `fetch`es it
   **from inside the page**, base64-encodes it and writes it to disk.

The scripts only touch the prompt UI. They never read cookies, tokens or API
keys from the page. That's deliberate: an attempt to read the API key off the
page was blocked, and it should stay off-limits. For API use, see
[The API route](#the-api-route-not-used-yet).

## One-time setup

```bash
npm install            # brings in playwright-core; no browser download needed

# A separate Chrome profile: Chrome refuses remote debugging on your default
# profile. Keep the profile somewhere permanent so the login survives.
mkdir -p ~/.config/aistudio-chrome
google-chrome --user-data-dir="$HOME/.config/aistudio-chrome" \
  --remote-debugging-port=9222 --no-first-run --no-default-browser-check \
  --new-window "https://aistudio.google.com/prompts/new_chat?model=gemini-nano-banana-2.1" \
  >/dev/null 2>&1 &

curl -s http://127.0.0.1:9222/json/version   # should print a "Browser" line
```

In that window: log in, dismiss any "OK, got it" dialogs, and make sure
**Nano Banana 2.1** is the selected model (the `?model=` URL above does it).
Then check that the scripts can see the page:

```bash
node scripts/studio/inspect.mjs   # prompt box, buttons, chat turns, images
```

While the port is open, any program on this machine can control that
logged-in window. Close Chrome when you're done generating.

## The scripts

Run them from the project root. Wrap them in `timeout` if you're scripting
them, in case a run hangs.

| Script | What it does |
|---|---|
| `new-chat.mjs` | Starts a fresh chat, so no earlier images are in context. |
| `settings.mjs <aspect> <res> [shot.png]` | Sets the aspect ratio (`16:9`, `1:1`, …) and resolution (`1K`/`2K`/`4K`), selects "Images only" and turns grounding off. Prints the options on offer. |
| `generate.mjs [--in image]… <out.jpg> <prompt files…>` | Joins the prompt files with blank lines, sends them as one message and saves the returned image. Each `--in` attaches an image to the message, e.g. a photo to edit. Stops early if AI Studio shows an error or declines. |
| `save-last.mjs <out.jpg>` | Saves the newest image in the chat, e.g. one you generated by hand. |
| `inspect.mjs` | Dumps the page elements the scripts rely on. Run it first when something breaks. |

**Run settings reset with every new chat**, so always run `settings.mjs`
after `new-chat.mjs`.

## Recipes

### A world plate, then the same place re-lit

```bash
node scripts/studio/new-chat.mjs
node scripts/studio/settings.mjs 16:9 2K
node scripts/studio/generate.mjs art/out/world-day-1.jpg art/prompts/style.md art/prompts/world-day.md
# Same chat: the day image is still in context, so this is an edit of it.
node scripts/studio/generate.mjs art/out/world-dusk-1.jpg art/prompts/world-dusk.md
```

The dusk prompt starts with "EDIT the attached image. Keep the exact same
composition…" and lists only what changes. Running it **in the same chat**
is what keeps the hills, house and clouds in place. No upload is needed.

### A set of characters that match

```bash
node scripts/studio/new-chat.mjs
node scripts/studio/settings.mjs 1:1 1K
node scripts/studio/generate.mjs art/out/figure-lantern-1.jpg \
  art/prompts/style.md art/prompts/figure-base.md art/prompts/figure-lantern.md
node scripts/studio/generate.mjs art/out/figure-sprout-1.jpg art/prompts/figure-next.md art/prompts/figure-sprout.md
node scripts/studio/generate.mjs art/out/figure-sleeper-1.jpg art/prompts/figure-next.md art/prompts/figure-sleeper.md
```

The first character gets the full style and base brief. Each later character
gets only `figure-next.md` ("match the previous character exactly in material,
texture, lighting, scale…") plus its own description, in the same chat.

### An edit of a photo you already have

```bash
node scripts/studio/generate.mjs --in art/out/figure-curled-1.jpg \
  art/out/figure-curled-blink-1.jpg art/prompts/figure-curled-blink.md
```

The closed-eye frames for the Rive figures, and the Kaleidoscope's lowered
pose, were made like this in the figure-set chat. Attaching the photo makes
the edit work from its exact pixels, not from whatever the chat last showed.
Even so, edits come back a few px off and with small changes elsewhere, so
take only the part you asked for (`scripts/blink-overlay.py`). An
in-between pose takes two attachments, the start and the end
(`figure-kaleidoscope-halfway.md`).

returns JPEG whatever extension you give, so name outputs `.jpg`.

## Prompts

They live in `art/prompts/` and are committed. The raw outputs go to
`art/out/`, which is gitignored.

- `style.md` is the shared look: soft surrealist storybook dream, 1970s film
  still, dusty pink, sage and cream, front-on stage-set composition, and a
  list of things to avoid. It goes first in every new chat. Later turns in
  that chat inherit it.
- One file per subject (`world-day.md`, `figure-lantern.md`, …), so you can
  recombine them.
- Edits and set continuations get their own short file (`world-dusk.md`,
  `figure-next.md`).
- Percentages in prompts are hints, not rules. We asked for the horizon at
  40% and got about 58%. Check the composition and regenerate if it matters;
  don't build layout around the numbers in the prompt.
- Figure prompts must ask for a **plain white background with only a soft
  contact shadow and clear space around the figure**. The cut-out step
  depends on it.

## From generated image to app asset

**World plates.** Convert them to WebP at two widths with ImageMagick:

```bash
for t in day dusk; do
  convert art/out/world-$t-1.jpg -resize 1600x -quality 82 -define webp:method=6 src/assets/world/world-$t-1600.webp
  convert art/out/world-$t-1.jpg -quality 80 -define webp:method=6 src/assets/world/world-$t-2752.webp
done
```

**Figures.** Cut them out of the white background and crop them to one shared
box (640×640, feet at 95% of the height), so their relative sizes survive:

```bash
python3 scripts/cutout-figures.py src/assets/figures art/out/figure-lantern-1.jpg art/out/figure-sprout-1.jpg art/out/figure-sleeper-1.jpg
```

Pass **all figures of a set in one run**, because the shared box size comes
from the largest one. The script removes the smooth, faintly tinted backdrop
by flood-filling from the border. Felt texture keeps pale figures from being
eaten, a second pass removes the near-white fringe, and seeds along the feet
line clear the gaps between legs. To check the result, composite it over a
loud colour:

```bash
convert -size 640x640 xc:'#d33' src/assets/figures/figure-sprout.webp -composite /tmp/check.png
```

After adding a new figure, measure where its feet and any glow points sit in
the 640 box. The per-look CSS variables in `src/styles/app.css` (`--shadow-x`,
`--shadow-w`, the lantern glow position) depend on them.

## Gotchas

- **The script never exits.** A CDP connection keeps Node alive until
  `browser.close()` is called. `withStudio()` in `connect.mjs` always does
  this. Inside a CDP connection that call only disconnects; your Chrome window
  stays open.
- **It saved HTML instead of an image.** While an image renders, the chat
  shows a placeholder `<img>` whose blob is `text/html`. `listImages()` only
  accepts `blob:` or `data:` sources that have finished loading and are wider
  than 256 px, and `generate.mjs` refuses a non-image blob. If a run still
  ends badly, use `save-last.mjs`.
- **"Project monthly spending cap reached."** Billing and quota problems show
  up as an error in the model's turn. `generate.mjs` stops on it instead of
  waiting 4 minutes. Raise the cap in AI Studio's billing settings, then
  rerun. The first day plate hit this. It was regenerated in the page by hand
  and saved from there.
- **The settings panel covers the prompt box** in narrow windows.
  `generate.mjs` closes it first.
- **Port 9222 is taken.** Another session's Chrome may already be listening
  on it. Start the AI Studio profile on another port
  (`--remote-debugging-port=9223`) and point the scripts at it with
  `STUDIO_CDP=http://127.0.0.1:9223`.
- **"Upgrade to unlock Nano Banana 2.1".** The account has a plan, so this
  means the window isn't logged in to it. Ask for a login; don't work around it.
- **An edit thinks for 3–4 minutes.** The model's turn shows "Thinking" and
  Run shows Stop for that long. `generate.mjs` waits up to 4 minutes for the
  image, and up to 6 for Run to come back.
- **Run starts a navigation, and the page can be swapped out.** A Playwright
  click on Run waits for that navigation, sometimes forever, so
  `generate.mjs` clicks it inside the page. When the page is swapped,
  `refind()` in `connect.mjs` finds the new one, reconnecting over CDP if the
  connection dropped. Every image in the chat then gets a new URL, so "which
  images are new" can't tell when the run is done. Instead, the run is done
  when the chat has grown, its last turn holds a `blob:` image and the turn
  before it holds the whole prompt. A swap can also drop the run: nothing
  is running and no answer comes. The script then stops and says so.
- **Run stays disabled** while the prompt box is empty and while an
  attachment is still being read. Ctrl+Enter then does nothing.
- **Uploads show up as image turns** with `data:` sources, named after the
  time of the upload, not the file. `listImages(page, false)` leaves them
  out.
- **"No image generated" or "An internal error has occurred."** The model
  sometimes declines an edit, or the run fails. `generate.mjs` stops on
  either. Delete the failed turns (the upload, the prompt and the answer)
  before rerunning, from each turn's "Open options" menu, so they don't
  pile up in the chat's context. Rerunning the same prompt didn't help:
  the whole Self-hug with its eyes shut was declined twice, once without
  its name in the prompt, and failed once with an internal error. A
  close-up of its face, with no "peaceful" in the prompt, went through on
  the first try.
- **"Allow Drive access to save this Prompt."** AI Studio can ask for this,
  and the dialog blocks the page. The user grants it themselves. Don't
  click Allow for them.
- **Keep the AI Studio window visible.** A screenshot of it timed out once,
  probably because Chrome throttles hidden windows.
- **AI Studio's markup will change.** The scripts rely on:
  - the textbox labelled "Enter a prompt"
  - `button.ctrl-enter-submits` (Run, which reads Stop while it runs)
  - `ms-add-media-button input.file-input` (attaching), `ms-prompt-image
    img.loaded-image` (an attachment read in) and the "Remove media" button
  - `ms-chat-turn` (chat turns) and `ms-image-chunk img` (generated images)
  - the buttons "New chat", "Toggle run settings panel" and "Close run
    settings panel"
  - the texts "Images only", "Aspect ratio" and "Resolution"
  - a switch whose label mentions Grounding

  If a script breaks, run `inspect.mjs` and update the selectors.

## The API route (not used yet)

`scripts/gen-image.mjs` does the same through the Gemini API. It takes
`--prompt` files, `--in` reference images for edits, `--aspect` and `--out`,
and reads `GEMINI_API_KEY` from `.env.local` (gitignored by `*.local`). It has
never been run because we had no key in the project. It's an option for batch
runs, if you put a key there yourself.
